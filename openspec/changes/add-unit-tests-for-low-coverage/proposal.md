# add-unit-tests-for-low-coverage

## 概要

テストカバレッジが0%の低カバレッジモジュールに対してユニットテストを追加し、全体のテストカバレッジを向上させる。

## 背景

現在のテストカバレッジは **53.66%** であり、以下のモジュールがテストされていない：

| モジュール | 行カバレッジ | 関数カバレッジ |
|-----------|------------|-------------|
| `src/cli.rs` | 0% | 0% |
| `src/llm/mod.rs` | 0% (0/5) | 0% (0/1) |
| `src/llm/anthropic.rs` | 0% (0/14) | 0% (0/3) |
| `src/llm/openai_compat.rs` | 0% (0/12) | 0% (0/3) |
| `src/commands/generate.rs` | 0% (0/35) | 0% (0/2) |
| `src/commands/backfill.rs` | 0% (0/99) | 0% (0/2) |
| `src/main.rs` | 0% (0/41) | 0% (0/2) |

これらのモジュールにテストがないことで、リファクタリングや機能追加時に回帰バグを検出できないリスクがある。

## 主要目標

### フェーズ1: 基本モジュールのテスト追加

以下の優先順位でユニットテストを追加：

1. **`src/cli.rs`** (優先度: 高)
   - CLIパーサーのテスト（サブコマンド、フラグ、引数）
   - 最も簡単で効果が高い

2. **`src/llm/mod.rs`** (優先度: 高)
   - `create_client` のプロバイダー振り分けロジック
   - 各プロバイダーの初期化テスト

3. **`src/llm/anthropic.rs`** (優先度: 中)
   - クライアント初期化のテスト
   - リクエストボディ構築のテスト

4. **`src/llm/openai_compat.rs`** (優先度: 中)
   - クライアント初期化のテスト
   - リクエストボディ構築のテスト

### フェーズ2: スコープ外（将来的に検討）

- `src/commands/generate.rs` - 統合テストが適切
- `src/commands/backfill.rs` - 統合テストが適切
- `src/main.rs` - E2Eテストが適切

## 受け入れ基準

1. `src/cli.rs` に以下のテストケースが追加されている：
   - サブコマンド（`generate`, `backfill`）のパース
   - グローバルオプション（`--provider`, `--model`）のパース
   - バリデーション（不正な値の拒否）

2. `src/llm/mod.rs` に以下のテストケースが追加されている：
   - 各プロバイダー（Anthropic, OpenAI, Gemini, DeepSeek）の振り分けが正しい
   - 不明なプロバイダーのエラーハンドリング

3. `src/llm/anthropic.rs` に以下のテストケースが追加されている：
   - `AnthropicClient::new` の初期化テスト
   - `build_request_body` のJSON構造テスト

4. `src/llm/openai_compat.rs` に以下のテストケースが追加されている：
   - `OpenAiCompatClient::new` の初期化テスト
   - `build_request_body` のJSON構造テスト

5. `cargo llvm-cov` でカバレッジが **60%以上** に向上している

## 影響範囲

- テストコードの追加のみ（プロダクションコードへの変更なし）
- CI/CDパイプラインでのカバレッジチェック追加（オプショナル）

## 非機能要件

- テストは高速に実行される（外部APIを呼び出さない）
- モックやスタブを適切に使用
- テストコードは保守しやすく、意図が明確
